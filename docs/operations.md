# 运维手册

## 备份与恢复

- 停止写入后直接复制整个 `DataDir`（含 `buckets/`）即完成冷备；
- 恢复：把备份目录放回目标路径，用相同配置（尤其加密主密钥）启动；
- 加密主密钥必须单独保管：丢失主密钥将无法解密任何对象；
- 建议备份后运行 `VerifyAll` 做一次完整性审计。

## 日常巡检

- 完整性：`VerifyAll(ctx, 4)` 全量校验 SHA256；
- 孤儿数据：`SweepOrphans(ctx)` 清理孤儿文件与过期分片会话；
- 生命周期：由 jobx 等调度器定期调用 `RunLifecycle(ctx, bucket)`；
- 容量：`BucketUsage` / `BucketStats` 监控对象数与字节量。
- 镜像：`Stats` 检查 pending / failed / 最近成功时间与复制延迟，
  定期抽检目标端 `ListAllVersions` 和 SHA256。

## 灾备镜像

- 源端必须保持单写，目标端只能作为灾备副本；
- `StateDir` 必须使用持久卷，并与源端对象数据目录分开；
- 首次启用时先执行一次 `Mirror`，确认对象、版本与删除标记数量一致；
- 常驻进程用 `go replicator.Run(ctx)` 周期对账；
- 失败任务先查看 `Tasks` 与日志；恢复目标后调用 `Replay` 立即重试；
- 目标桶中的手工写入会被按源端状态对账并删除，禁止在目标端执行业务写；
- 网络必须使用 TLS；跨区域链路建议同时启用 Bearer/HMAC 鉴权。

## 服务健康

- 单实例内调用 `Store.Health`；
- 协议端点 `GET /filex/v1/health` 供负载均衡存活探针；
- 指标：`HandlerConfig.Metrics` 注入请求成功率与错误分布。

## 安全基线

- 公网部署必须 TLS（HTTP/3 或 HTTPS），禁止明文 HTTP；
- 开启鉴权后客户端必须携带时间戳与签名/令牌；
- 建议开启静态加密并把主密钥交给密钥管理系统；
- 审计回调落盘便于事后追溯。

## 升级流程

- 当前模块 Go 基线为 1.27.4；
- 遵循语义化版本；v1.*.* 不承诺向后兼容；
- 升级前备份 DataDir 与主密钥；
- 升级后运行 `VerifyAll` 与示例自检。

## 已知边界

- 单机单盘存储模型不变；跨区域异步单写镜像由可选
  `filex/replication` 提供，多主写入冲突合并与纠删码不在范围内；
- 配额与统计为扫描式，万级对象内开销可接受；
- 加密对象不支持 Range 读取。

## 加密格式迁移

v0.17.0 起静态加密采用分块 AES-256-GCM；v0.5–v0.16 的 CTR 加密对象
需在升级后重新写入（读取旧对象会报错）。
