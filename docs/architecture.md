# filex 架构详解

## 1. 存储布局

```
<DataDir>/
└── buckets/
    ├── <bucket>/
    │   ├── meta.json              # 桶元数据（名称/创建时间/配额等）
    │   ├── objects/
    │   │   ├── <sha256(key)>.json # 非版本化对象元数据
    │   │   ├── <sha256(key)>.data # 非版本化对象内容
    │   │   ├── <sha256(key)>/     # 版本化对象目录
    │   │   │   ├── v-<id>.json    # 版本元数据（含删除标记）
    │   │   │   └── v-<id>.data    # 版本内容
    │   │   └── .uploads/<id>/     # 分片上传会话（孤儿巡检跳过）
    │   └── ...
```

说明：

- 对象目录名是键的 SHA256，键本身只存在于元数据中：
  - 路径穿越不可达（键再恶意也只是哈希目录名）；
  - 目录名长度固定，规避 Windows 长路径问题；
  - 哈希冲突理论上存在，元数据中保存原始键，写入前校验冲突并拒绝；
- 元数据与数据分离：列表扫描只读 JSON，不触碰大文件；
- 版本化桶按 `<sha>/v-<id>` 组织，删除写入“删除标记”而非物理删除；
- 启用静态加密时，数据文件前缀为 16 字节随机 nonce，正文为
  AES-256-CTR 密文；DEK 由主密钥 AES-GCM 包装后存入元数据；
- 整个 DataDir 就是一份可备份目录，停止写入后可直接冷备。

## 2. 原子性与一致性

### 2.1 对象写入

1. 写入 `<sha>.tmp.<随机>` 临时文件，边写边算 SHA256；
2. `fsync` 临时文件；
3. `rename` 临时文件为 `<sha>.data`（同目录，跨平台原子）；
4. 序列化元数据到 `<sha>.meta.json.tmp`，`fsync` 后 rename 为
   `<sha>.meta.json`；
5. 返回成功。

meta 最后生效：崩溃时最多出现“data 存在但 meta 不存在”的孤儿文件，
不会出现“meta 指向不完整 data”。

### 2.2 对象删除

先删 `meta.json`，再删 `data`。若删除中断，可能出现孤儿 data，
由后续 `List` 与 `Delete` 的孤儿清理逻辑回收（v0.1.0 起内置）。

### 2.3 桶删除

仅允许删除空桶；版本化桶中仅剩删除标记时视为空桶。

## 3. 并发模型

- `Store` 内部使用**分片读写锁**（默认 64 片，FNV-1a 哈希桶/键）：
  - 同键写写互斥、写读互斥；
  - 不同键完全并行；
  - 桶创建/删除使用桶级锁；
- 同一键并发 `Put`：后完成者生效（原子 rename 保证内容完整），
  双方各自返回成功；需要严格“最后写入者胜”语义由调用方控制；
- `List` 与写入并发：读到的是快照（每对象 meta 原子可见），
  不保证全局线性一致，符合对象存储常规语义。

## 4. 键与桶校验

- 桶名：3-63 位，小写字母/数字/连字符，首尾必须字母或数字；
- 键：1-1024 字节，允许任意 UTF-8（不含 NUL），不允许 `.` 与 `..`；
- 键不参与文件系统路径拼接（哈希目录），杜绝目录穿越。

## 5. 完整性

- 写入强制计算 SHA256；`ExpectedSHA256` 提供时逐字节比对；
- ETag 定义为内容 SHA256 的十六进制小写；
- 读取可选复验：`GetOptions.Verify=true` 时流式哈希，EOF 校验；
- 元数据 JSON 使用 `json.Decoder` 严格解码，未知/缺失关键字段视为损坏。

## 6. 平台差异

| 平台 | 说明 |
| --- | --- |
| Unix | `rename` 原子；目录 fsync 尽力而为（可用时执行） |
| Windows | `os.Rename` 对已存在目标在 Go 中为原子替换；临时文件同目录保证同卷 |
| 路径 | 所有路径经 `filepath.Join` 拼接，对象目录固定长度，规避长路径 |

## 7. 可观测

- 日志事件：bucket 创建/删除、对象 put/get/head/delete/list、
  校验失败、孤儿清理；字段含 bucket/key/bytes/duration/error_code；
- 指标：`Metrics` 接口提供 `Add(bucket, operation, bytes)` 与
  `IncError(bucket, code)`，业务可对接 metricsx；
- 请求 ID：协议层（v0.2.0）为每个请求生成，贯穿日志与错误响应。

## 8. 生命周期与孤儿巡检

- `RunLifecycle` 按桶配置执行：过期对象物理删除、版本化桶按
  `MaxVersions` 收敛旧版本；
- `SweepOrphans` 清理“有数据无元数据”的孤儿文件、临时文件与空版本目录；
- 分片上传会话目录 `.uploads` 由上传流程管理，孤儿巡检明确跳过。
